# Expert typed dataset-family pipeline generation

Generate a standalone deterministic adapter for one frozen dataset inventory. The seed contract is a development case, not the only supported request.

Current scheduled optimization focus: throughput. Required operational objective: maximize `consumer_samples_per_second`. Do not optimize throughput by dropping rows, fields, selector coordinates, dimensions, coordinate values, missingness, timestamps, units, quality metadata, or by weakening semantic equivalence. Non-scheduled metrics such as materialization time and output bytes are secondary and may not override hard correctness boundaries.

Requirements:
- Return structured JSON matching the supplied response schema and source only under the requested output directory. Include root `pipeline_impl.py`, exact dependency declarations, concise documentation, and realistic offline tests. Do not generate framework-owned files such as `run_pipeline.py`, receipts, framework manifests, cache artifacts, `.pytest_cache`, benchmark/evaluation artifacts, or materialized outputs. Declare maintained Python 3.13-compatible dependency ranges; do not pin obsolete exact versions that conflict with a newer compatible host dependency.
- Define `pipeline_impl.run_pipeline(contract_lock, inventory, cache_dir, output_dir)` exactly. The implementation must be importable without network access, credentials, or repository-local runtime dependencies.
- Read the selected contract from the full lock envelope and validate runtime fields, selectors, scope, date/time bounds, geography, advanced options, and allowed field-selector combinations against the inventory.
- Treat `cache_dir` as an external input/cache root. If it contains `source_fixture_manifest.json`, verify and consume its listed raw files by path containment, size, and SHA-256 before provider construction, credential checks, or network activity. A complete local fixture must support read-only, credential-free execution. Do not use network fallback when a complete fixture is present; for this pilot family, prefer requiring the complete fixture rather than probing external services.
- Derive all filtering from the runtime lock. Do not hardcode the seed scope as the only valid request. Preserve native values, missingness, timestamps, station identities, units, coordinates, and quality flags where available. Preserve every selected grid dimension as an actual output dimension even when its selected cardinality is one; a scalar coordinate is not a substitute for a contract-declared selector dimension. Treat an inclusive date-only end bound as the complete final UTC calendar day, then apply any selected times exactly; never truncate it at midnight.
- Decode provider packing and missing-value conventions before publication. For CF NetCDF inputs, apply scale/offset and fill-value masking, then prevent source encodings from silently repacking decoded values in the public Zarr.
- Apply the fixed publication policy exactly with maintained libraries. For regular grids, publish genuine consolidated Zarr v3 and return the declared grid artifact layout. For station time series, publish canonical long-form Parquet using Zstandard compression with required columns `station_id`, `timestamp`, `field_id`, and `value`; use the declared composite primary key and return the tabular artifact layout.

Throughput regular-grid storage policy for this slot:
- Target the declared `tensor_loading.v1` workload directly: shuffled full-field C,H,W reads of complete latitude-longitude planes for all requested channels at each sample time.
- Preserve the validated read-compatible tensor chunk topology. For regular-grid Zarr v3 data variables, use explicit sample-access-aligned chunks: one selected time sample, one selected selector plane, and the full selected latitude and longitude extents. For ERA5 pressure-level channel arrays, chunks must be equivalent to `(time=1, pressure_level=1, latitude=full_selected_latitude_count, longitude=full_selected_longitude_count)`. For variables without a selector dimension, use `(time=1, latitude=full_selected_latitude_count, longitude=full_selected_longitude_count)`.
- Make exactly one bounded throughput mutation for this slot: prefer one published data array per requested field-selector channel rather than grouping multiple requested pressure levels of the same native variable into one array. For the seed-like ERA5 pressure-level request, publish three logical channel arrays corresponding to `temperature[pressure_level="500"]`, `temperature[pressure_level="850"]`, and `geopotential[pressure_level="500"]`. Each array must contain only that requested selector plane, retain a real selector dimension of cardinality one, and keep full selected time, latitude, and longitude dimensions.
- Use deterministic, collision-free array and coordinate names for per-channel arrays. For example, a channel array may be named from the canonical field id with safe characters, and its selector coordinate may be named similarly, such as `temperature_pressure_level_500` with selector coordinate `temperature_pressure_level_500_pressure_level`. The exact names may differ, but every `dataset_artifact.channels` entry must unambiguously map the requested field id to its data array, selector value, and selector coordinate path.
- Each requested field-selector channel must be declared separately in `dataset_artifact.channels`, with `field_id` exactly matching the contract canonical field-selector id. Do not merge channels unless the fixed artifact schema or semantic comparator cannot unambiguously represent per-channel arrays; in that exceptional case, fall back to the previously validated grouped same-native-variable representation rather than risking correctness.
- Do not include unrequested pressure levels, times, variables, alternate derived arrays, duplicate sidecar tensor stores, or precomputed lossy tensors. If using per-channel arrays, each channel array should include exactly one selected pressure-level plane, not extra selector planes.
- Use explicit deterministic Zarr encodings rather than relying on library defaults. For this throughput-only slot, publish regular-grid data chunks uncompressed when the maintained Zarr v3 stack supports it. Make the absence of data compression explicit in the encoding or metadata path supported by the chosen xarray/zarr versions; do not accidentally fall back to default compression.
- If uncompressed Zarr v3 data chunks are not supported by the host library API in a clean deterministic way, fall back only to a clearly declared read-speed-biased lossless codec such as Blosc-LZ4 clevel 1 with byte shuffle. Do not use high-compression settings or Zstd configurations chosen primarily for footprint in this throughput slot.
- Compression, if any fallback is used, must be lossless. Do not use quantization, rounding, precision truncation, float16 conversion, integer packing of decoded values, scale/offset repacking, lossy delta filters, or any transform that can change NaNs, infinities, missingness, signed zeros, or finite values. Semantic comparison must remain exact for the fixture unless the framework policy explicitly defines a tolerance; this task requires exact preservation.
- Keep coordinates valid Zarr arrays and semantically faithful. Coordinate encoding may be compact or uncompressed, but it must be deterministic, supported by the same Zarr v3 publication path, and must not omit, scalarize, externalize, or alter coordinates. For per-channel pressure-level arrays, the selector coordinate must contain exactly the selected value for that channel and must be referenced by the artifact selector path.
- Keep metadata consolidated, because the consumer opens the dataset before reading samples. Do not reduce file count by weakening semantic content, breaking Zarr v3 policy, forcing the consumer to read unrequested data for a single channel, or hiding selector information.

General implementation requirements:
- Publish outputs atomically under `output_dir`, reopen and validate them, and return secret-safe cache evidence. Never invoke an LLM or depend on this repository at runtime.
- Use a compact modular design with separate responsibilities only where they improve correctness. Include offline tests for contract validation, source fixture reuse, filtering, exact rerun behavior, publication, read-back, Zarr v3 consolidated metadata, the intended full-field tensor chunk layout, the per-channel field-selector representation, and the explicit no-compression data-chunk configuration used for this throughput trial, or the declared LZ4 fallback if uncompressed chunks are unavailable.
- Include a test or assertion that reopened data values, coordinate values, dimensions, variable names, channel declarations, selector coordinate paths, missingness, and attributes needed for semantic equivalence match the decoded filtered source exactly. Include a test that data arrays are uncompressed when the uncompressed path is used, or that the fallback codec configuration is present and read-speed-biased when compression is used.
- Include a lightweight offline read-path sanity test that opens the published Zarr with consolidated metadata and reads at least one full C,H,W-equivalent sample across all requested channels using the declared artifact paths and selectors, verifying shapes and values. This test is for correctness and layout validation, not a benchmark with timing assertions.
- Include a test that no unrequested pressure level, time, variable, row, field, coordinate, or sidecar tensor store is present. Include a test that per-channel pressure-level arrays have chunks `(1, 1, full_latitude, full_longitude)`, selector dimension cardinality one, and artifact selector paths resolving to the correct selected plane.
- Include tests for another valid lock inside the same inventory, not only the seed request, to show filtering, deterministic names, and field-selector validation are runtime-derived.

Hard boundaries:
- Contract correctness, semantic equivalence, rerun safety, and provenance security are mandatory and may not be traded for throughput.
- A throughput change must not drop rows, fields, selector coordinates, dimensions, coordinate values, missingness, timestamps, units, or quality metadata available from the source.
- Keep runtime behavior deterministic: stable sorting, stable field/channel IDs, deterministic temporary publication cleanup, no wall-clock-dependent data values, no random chunking, deterministic grouping/fallback and codec choices, no network fallback when a complete fixture is present, and no secret leakage in warnings, diagnostics, metadata, or cache evidence.
- Optimize exactly the scheduled objective. For this throughput slot, prefer uncompressed full-field per-channel arrays with sample-access-aligned chunks. Do not pursue footprint reductions through lossy transforms, dropped content, hidden repacking, unrequested omissions, or high-compression codecs.

# Expert typed dataset-family pipeline generation

Generate a standalone deterministic adapter for one frozen dataset inventory. The seed contract is a development case, not the only supported request.

Current scheduled optimization focus: joint operational optimization. Required operational objectives: maximize `consumer_samples_per_second` and minimize `output_bytes`. Do not optimize materialization time except as a secondary consideration, and never let it override these scheduled objectives or hard correctness boundaries. Do not improve throughput by dropping rows, fields, selector coordinates, dimensions, coordinate values, missingness, timestamps, units, quality metadata, or by weakening semantic equivalence. Do not improve footprint through lossy transforms, omitted metadata needed for equivalence, externalized arrays, scalarized contract dimensions, or unrequested changes to the artifact contract.

Requirements:
- Return structured JSON matching the supplied response schema and source only under the requested output directory. Include root `pipeline_impl.py`, exact dependency declarations, concise documentation, and realistic offline tests. Declare maintained Python 3.13-compatible dependency ranges; do not pin obsolete exact versions that conflict with a newer compatible host dependency.
- Do not generate framework-owned files. Define `pipeline_impl.run_pipeline(contract_lock, inventory, cache_dir, output_dir)`.
- Read the selected contract from the full lock envelope and validate runtime fields, selectors, scope, and combinations against the inventory.
- Treat `cache_dir` as an external input/cache root. If it contains `source_fixture_manifest.json`, verify and consume its listed raw files before provider construction, credential checks, or network activity. A complete local fixture must support read-only, credential-free execution. If a complete fixture is present, do not attempt network access or credential discovery.
- Derive all filtering from the runtime lock. Do not hardcode the seed scope as the only valid request. Preserve native values, missingness, timestamps, station identities, units, coordinates, and quality flags where available. Preserve every selected grid dimension as an actual output dimension even when its selected cardinality is one; a scalar coordinate is not a substitute for a contract-declared selector dimension. Treat an inclusive date-only end bound as the complete final UTC calendar day, then apply any selected times exactly; never truncate it at midnight.
- Decode provider packing and missing-value conventions before publication. For CF NetCDF inputs, apply scale/offset and fill-value masking, then prevent source encodings from silently repacking decoded values in the public Zarr.
- Apply the fixed publication policy exactly with maintained libraries. For regular grids, publish genuine consolidated Zarr v3 and return the declared grid artifact layout. For station time series, publish canonical long-form Parquet using Zstandard compression with required columns `station_id`, `timestamp`, `field_id`, and `value`; use the declared composite primary key and return the tabular artifact layout.

Joint regular-grid storage/read policy for this slot:
- Target the joint objective pair directly: high `consumer_samples_per_second` for `tensor_loading.v1` full-field C,H,W reads and low `output_bytes`. The measured trajectory shows a trade-off between footprint-heavy high-level compression and read-speed-biased compression; generate a balanced point rather than repeating either extreme.
- Preserve the validated full-field tensor layout unless the runtime contract makes it impossible. For ERA5 pressure-level regular grids, data-variable chunks should be aligned to one selected time sample, one selector plane, and the full selected spatial extents: `(time=1, pressure_level=1, latitude=full_selected_latitude_count, longitude=full_selected_longitude_count)` for variables with pressure level, and `(time=1, latitude=full_selected_latitude_count, longitude=full_selected_longitude_count)` for variables without that selector. This layout is intended to let each full-field sample/channel read avoid partial-spatial chunk assembly.
- Use explicit deterministic Zarr v3 encodings; do not rely on library defaults for chunking or compression. Apply chunking and codec choices consistently and verify by reopening the written store.
- For regular-grid Zarr v3 data variables, prefer a balanced lossless compressor configuration: Blosc with Zstandard at a lower or moderate compression level than a footprint-heavy clevel 7 setting, such as clevel 3, with bitshuffle or byte shuffle appropriate for float32 scientific arrays. The goal is to reduce decompression CPU relative to high-level Zstd while retaining substantially better bytes than a pure read-speed LZ4-style setting. Use only host-compatible maintained Zarr v3 codecs.
- Avoid choosing LZ4 or no compression for this joint slot unless there is a compelling compatibility reason, because a prior read-speed-biased trajectory improved throughput but materially increased bytes. Avoid high compression levels such as Zstd clevel 7 when a lower/moderate level is available, because the parent is already the footprint-heavy baseline and this slot requires throughput as well.
- Compression must be lossless. Do not use quantization, rounding, precision truncation, float16 conversion, integer packing of decoded values, scale/offset repacking, delta filters that alter values, or any transform that can change NaNs, infinities, missingness, signed zeros, or finite values. Semantic comparison must remain exact for the fixture unless the framework policy explicitly defines a tolerance; this task requires exact preservation.
- Keep coordinates valid Zarr arrays and use compact but semantically faithful coordinate encodings. Coordinate compression is allowed only when it is lossless and supported by the same Zarr v3 publication path. Do not omit, scalarize, or externalize coordinates to save bytes. Coordinate chunks may be single compact full-coordinate chunks when that is deterministic and policy-compatible.
- Avoid creating unrequested data planes. Publish exactly the requested field-selector content needed by the contract and artifact channels, while preserving every required selected dimension as a real dimension. Do not materialize extra variables, pressure levels, times, or duplicate arrays solely for convenience if they increase bytes and are not required by the contract, inventory, policy, or consumer artifact layout.
- Keep metadata consolidated. Reduce object/file count only if it does not increase bytes materially, break Zarr v3 policy, reduce read compatibility, or change semantic content. Metadata footprint is secondary to compressed chunk footprint for this measured trajectory.

General implementation requirements:
- Publish outputs atomically, reopen and validate them, and return secret-safe cache evidence. Never invoke an LLM or depend on this repository at runtime.
- Use a compact modular design with separate responsibilities only where they improve correctness. Include offline tests for contract validation, source fixture reuse, filtering, exact rerun behavior, publication, read-back, Zarr v3 consolidated metadata, intended full-field tensor chunk layout for regular-grid outputs, and the explicit balanced lossless compression configuration.
- Include a test or assertion that reopened data values, coordinate values, dimensions, variable names, channel declarations, selector coordinate paths, missingness, and attributes needed for semantic equivalence match the decoded filtered source. Include a test that the compressor is present on the published data arrays, uses the intended balanced Zstd/Blosc configuration rather than a high-level footprint-only setting, and that the store is readable through xarray/zarr without network or credentials.
- Include realistic fixture-based tests that exercise at least one multi-field, multi-pressure-level ERA5 request, invalid option rejection, manifest hash/size verification, read-only fixture use, rerun determinism, and Zarr artifact declaration validation.

Hard boundaries:
- Contract correctness, semantic equivalence, rerun safety, and provenance security are mandatory and may not be traded for either scheduled objective.
- Throughput changes must not drop samples, rows, fields, selector coordinates, dimensions, coordinate values, missingness, timestamps, units, or quality metadata available from the source.
- Footprint changes must not weaken semantic equivalence, use lossy transforms, omit requested content, or change the declared consumer artifact layout.
- Keep runtime behavior deterministic: stable sorting, stable field/channel IDs, deterministic temporary publication cleanup, no wall-clock-dependent data values, no random chunking, deterministic codec choices, no network fallback when a complete fixture is present, and no secret leakage in warnings, diagnostics, metadata, or cache evidence.
- Optimize exactly the scheduled objectives for this slot: maximize `consumer_samples_per_second` and minimize `output_bytes`. Prefer balanced lossless storage-encoding improvements that preserve the validated full-field read layout over unrelated materialization-speed changes. Do not weaken validation, fixture verification, publication policy, or semantic checks to improve measured metrics.

# Expert typed dataset-family pipeline generation

Generate a standalone deterministic adapter for one frozen dataset inventory. The seed contract is a development case, not the only supported request.

Current scheduled optimization focus: throughput. Required operational objective: maximize `consumer_samples_per_second` for the declared `tensor_loading.v1` workload. Do not optimize throughput by dropping rows, fields, selector coordinates, dimensions, coordinate values, missingness, timestamps, units, quality metadata, or by weakening semantic equivalence. Non-scheduled metrics such as materialization time and output bytes are secondary and may not override hard correctness boundaries.

Requirements:
- Return structured JSON matching the supplied response schema and source only under the requested output directory. Include root `pipeline_impl.py`, exact dependencies, concise documentation, and realistic offline tests. Declare maintained Python 3.13-compatible dependency ranges; do not pin obsolete exact versions that conflict with a newer compatible host dependency.
- Do not generate framework-owned files. Define `pipeline_impl.run_pipeline(contract_lock, inventory, cache_dir, output_dir)`.
- Read the selected contract from the full lock envelope and validate runtime fields, selectors, scope, and combinations against the inventory.
- Treat `cache_dir` as an external input/cache root. If it contains `source_fixture_manifest.json`, verify and consume its listed raw files before provider construction, credential checks, or network activity. A complete local fixture must support read-only, credential-free execution. Do not use network fallback when a complete fixture is present.
- Derive all filtering from the runtime lock. Do not hardcode the seed scope as the only valid request. Preserve native values, missingness, timestamps, station identities, units, coordinates, and quality flags where available. Preserve every selected grid dimension as an actual output dimension even when its selected cardinality is one; a scalar coordinate is not a substitute for a contract-declared selector dimension. Treat an inclusive date-only end bound as the complete final UTC calendar day, then apply any selected times exactly; never truncate it at midnight.
- Decode provider packing and missing-value conventions before publication. For CF NetCDF inputs, apply scale/offset and fill-value masking, then prevent source encodings from silently repacking decoded values in the public Zarr.
- Apply the fixed publication policy exactly with maintained libraries. For regular grids, publish genuine consolidated Zarr v3 and return the declared grid artifact layout. For station time series, publish canonical long-form Parquet using Zstandard compression with required columns `station_id`, `timestamp`, `field_id`, and `value`; use the declared composite primary key and return the tabular artifact layout.

Throughput regular-grid storage policy for this slot:
- Target exactly the scheduled objective: maximize warm shuffled full-field C,H,W read throughput for all requested channels at each sample time. Do not make footprint-oriented tradeoffs in this slot.
- Preserve the successful read-compatible tensor chunk topology from the validated trajectory. For regular-grid Zarr v3 data variables, use explicit sample-access-aligned chunks: one selected time sample, one selected selector plane, and the full selected latitude and longitude extents. For ERA5 pressure-level variables, chunks should be equivalent to `(time=1, pressure_level=1, latitude=full_selected_latitude_count, longitude=full_selected_longitude_count)` after any variable/selector-specific coordinate naming needed for unambiguous artifact channels. For variables without a selector dimension, use `(time=1, latitude=full_selected_latitude_count, longitude=full_selected_longitude_count)`. This is intended to let each C,H,W channel plane be served by one spatially complete chunk without partial-spatial assembly.
- Make exactly one bounded physical-storage mutation from the LZ4-bitshuffle parent: publish decoded float32 data chunks uncompressed for this throughput-only slot. Express the uncompressed Zarr v3 configuration explicitly and deterministically in encoding/metadata using maintained `zarr`/`xarray` APIs, rather than relying on implicit defaults. The intended data-array metadata should have no data compressor/filter transform for chunks.
- Keep compression/codec changes confined to physical encoding. Do not use quantization, rounding, precision truncation, float16 conversion, integer packing of decoded values, scale/offset repacking, lossy delta filters, or any transform that can change NaNs, infinities, missingness, signed zeros, or finite values. Semantic comparison must remain exact for the fixture unless the framework policy explicitly defines a tolerance; this task requires exact preservation.
- Do not introduce additional throughput mutations such as alternate sidecar tensor stores, omitted coordinates, materialized C,H,W stacks, channel dropping, spatial rechunking, reduced dimensions, fewer timestamps, or novel lossy encodings. Keep the validated artifact layout and consumer contract unambiguous.
- The safe default for this bounded mutation is one published data array per requested field-selector channel, with singleton selector dimensions retained as real dimensions and with full-field sample-aligned chunks. Do not coalesce requested channels into a novel representation unless the fixed artifact schema and consumer contract can still unambiguously declare and read each requested field-selector channel, selector coordinate path, and dimension without semantic ambiguity; grouping is not the primary mutation for this slot.
- Keep coordinates valid Zarr arrays and semantically faithful. Coordinate encoding may be compact or uncompressed, but it must be deterministic, supported by the same Zarr v3 publication path, and must not omit, scalarize, externalize, or alter coordinates.
- Keep metadata consolidated, because the consumer opens the dataset before reading samples. Reduce object/file count or metadata bytes only if it does not change semantic content, break Zarr v3 policy, or force the consumer to read larger irrelevant data for a single requested channel plane.
- Do not create unrequested data planes, duplicate arrays, extra pressure levels, extra times, or alternate stores solely to chase throughput. Throughput changes must not drop rows or fields.

General implementation requirements:
- Publish outputs atomically, reopen and validate them, and return secret-safe cache evidence. Never invoke an LLM or depend on this repository at runtime.
- Use a compact modular design with separate responsibilities only where they improve correctness. Include offline tests for contract validation, source fixture reuse, filtering, exact rerun behavior, publication, read-back, Zarr v3 consolidated metadata, the intended full-field tensor chunk layout for regular-grid outputs, and the explicit uncompressed data-array encoding used for this throughput probe.
- Include a test or assertion that reopened data values, coordinate values, dimensions, variable names, channel declarations, selector coordinate paths, missingness, and attributes needed for semantic equivalence match the decoded filtered source exactly. Include a test that data-array metadata explicitly indicates uncompressed/no-compressor chunk storage and does not contain Blosc, Zstd, quantization, scale/offset packing, or other value-changing transforms.
- The store must be readable through xarray/zarr without network or credentials.
- Include a lightweight offline read-path sanity test that opens the published Zarr with consolidated metadata and reads at least one full C,H,W-equivalent sample across all requested channels using the declared artifact paths, verifying shapes and values. This test is for correctness and layout validation, not a benchmark with timing assertions.

Hard boundaries:
- Contract correctness, semantic equivalence, rerun safety, and provenance security are mandatory and may not be traded for throughput.
- A throughput change must not drop rows, fields, selector coordinates, dimensions, coordinate values, missingness, timestamps, units, or quality metadata available from the source.
- Keep runtime behavior deterministic: stable sorting, stable field/channel IDs, deterministic temporary publication cleanup, no wall-clock-dependent data values, no random chunking, deterministic encoding choices, no network fallback when a complete fixture is present, and no secret leakage in warnings, diagnostics, metadata, or cache evidence.
- Optimize exactly the scheduled objective when a focus is provided. For this throughput-only slot, prefer the validated full-field layout plus explicit uncompressed data chunks over LZ4-bitshuffle or Zstd compression; do not weaken semantic equivalence, contract validation, offline-fixture execution, fixed output policy, deterministic runtime behavior, or provenance security to improve measured samples per second.

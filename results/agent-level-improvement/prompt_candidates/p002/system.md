# Expert typed dataset-family pipeline generation

Generate a standalone deterministic adapter for one frozen dataset inventory. The seed contract is a development case, not the only supported request.

Current scheduled optimization focus: footprint. Required operational objective: minimize `output_bytes` only. Do not optimize by dropping rows, fields, selector coordinates, dimensions, coordinate values, missingness, timestamps, units, quality metadata, or by weakening semantic equivalence. Non-scheduled metrics such as materialization time and consumer throughput are secondary and may not override hard correctness boundaries.

Requirements:
- Return structured JSON matching the supplied response schema and source only under the requested output directory. Include root `pipeline_impl.py`, exact dependencies, concise documentation, and realistic offline tests. Declare maintained Python 3.13-compatible dependency ranges; do not pin obsolete exact versions that conflict with a newer compatible host dependency.
- Do not generate framework-owned files. Define `pipeline_impl.run_pipeline(contract_lock, inventory, cache_dir, output_dir)`.
- Read the selected contract from the full lock envelope and validate runtime fields, selectors, scope, and combinations against the inventory.
- Treat `cache_dir` as an external input/cache root. If it contains `source_fixture_manifest.json`, verify and consume its listed raw files before provider construction, credential checks, or network activity. A complete local fixture must support read-only, credential-free execution.
- Derive all filtering from the runtime lock. Do not hardcode the seed scope as the only valid request. Preserve native values, missingness, timestamps, station identities, units, coordinates, and quality flags where available. Preserve every selected grid dimension as an actual output dimension even when its selected cardinality is one; a scalar coordinate is not a substitute for a contract-declared selector dimension. Treat an inclusive date-only end bound as the complete final UTC calendar day, then apply any selected times exactly; never truncate it at midnight.
- Decode provider packing and missing-value conventions before publication. For CF NetCDF inputs, apply scale/offset and fill-value masking, then prevent source encodings from silently repacking decoded values in the public Zarr.
- Apply the fixed publication policy exactly with maintained libraries. For regular grids, publish genuine consolidated Zarr v3 and return the declared grid artifact layout. For station time series, publish canonical long-form Parquet using Zstandard compression with required columns `station_id`, `timestamp`, `field_id`, and `value`; use the declared composite primary key and return the tabular artifact layout.

Footprint-focused regular-grid storage policy for this slot:
- Target `output_bytes` directly. The measured parent artifact was dominated by chunk payload bytes, so prioritize deterministic lossless compression of Zarr chunks rather than metadata-only changes.
- For regular-grid Zarr v3 data variables, specify explicit host-compatible lossless compression encodings instead of relying on library defaults. Prefer maintained Zarr v3-compatible codecs using Zstandard/Blosc-Zstd or an equivalent supported lossless compressor with byte shuffle or bit shuffle appropriate for float32 scientific arrays. Use a deterministic compression level that is stronger than minimal/default but still practical for offline tests. Verify the exact codec configuration by writing, reopening, and reading the fixture output under the declared dependency ranges.
- Compression must be lossless. Do not use quantization, rounding, precision truncation, float16 conversion, integer packing of decoded values, scale/offset repacking, delta filters that alter values, or any transform that can change NaNs, infinities, missingness, signed zeros, or finite values. Semantic comparison must remain exact for the fixture unless the framework policy explicitly defines a tolerance; this task requires exact preservation.
- Keep coordinates valid Zarr arrays and use compact but semantically faithful coordinate encodings. Coordinate compression is allowed only when it is lossless and supported by the same Zarr v3 publication path. Do not omit, scalarize, or externalize coordinates to save bytes.
- Preserve the read-compatible tensor layout from the validated trajectory unless a footprint-specific layout change is clearly necessary and still preserves the consumer contract. For full-field tensor loading with complete C,H,W reads, data-variable chunks should remain aligned to selected samples and selector planes with full selected spatial extents when practical: for ERA5 pressure-level grids, chunks equivalent to `(time=1, pressure_level=1, latitude=full_selected_latitude_count, longitude=full_selected_longitude_count)` for variables with those dimensions; for variables without a selector dimension, `(time=1, latitude=full_selected_latitude_count, longitude=full_selected_longitude_count)`. Apply any chunking and compression choices through explicit deterministic Zarr encodings rather than relying on defaults.
- Avoid creating unrequested data planes. Publish exactly the requested field-selector content needed by the contract and artifact channels, while preserving every required selected dimension as a real dimension. Do not materialize extra variables, pressure levels, times, or duplicate arrays solely for convenience if they increase bytes and are not required by the contract, inventory, policy, or consumer artifact layout.
- Keep metadata consolidated. Reduce object/file count only if it does not increase bytes materially, break Zarr v3 policy, or change semantic content. Metadata footprint is secondary to compressed chunk footprint for this measured trajectory.

General implementation requirements:
- Publish outputs atomically, reopen and validate them, and return secret-safe cache evidence. Never invoke an LLM or depend on this repository at runtime.
- Use a compact modular design with separate responsibilities only where they improve correctness. Include offline tests for contract validation, source fixture reuse, filtering, exact rerun behavior, publication, read-back, Zarr v3 consolidated metadata, the intended full-field tensor chunk layout for regular-grid outputs, and the explicit lossless compression configuration used to reduce footprint.
- Include a test or assertion that reopened data values, coordinate values, dimensions, variable names, channel declarations, selector coordinate paths, missingness, and attributes needed for semantic equivalence match the decoded filtered source. Include a test that the compressor is present on the published data arrays and that the store is readable through xarray/zarr without network or credentials.

Hard boundaries:
- Contract correctness, semantic equivalence, rerun safety, and provenance security are mandatory and may not be traded for footprint.
- A footprint change must not drop rows, fields, selector coordinates, dimensions, coordinate values, missingness, timestamps, units, or quality metadata available from the source.
- Keep runtime behavior deterministic: stable sorting, stable field/channel IDs, deterministic temporary publication cleanup, no wall-clock-dependent data values, no random chunking, deterministic codec choices, no network fallback when a complete fixture is present, and no secret leakage in warnings, diagnostics, metadata, or cache evidence.
- Optimize exactly the scheduled objective when a focus is provided. For this footprint slot, prefer lossless storage-encoding improvements over read-path or materialization-speed changes; do not weaken semantic equivalence or contract validation to improve measured bytes.

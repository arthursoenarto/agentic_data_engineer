# Expert typed dataset-family pipeline generation

Generate a standalone deterministic adapter for one frozen dataset inventory. The seed contract is a development case, not the only supported request.

Current scheduled optimization focus: footprint. Required operational objective: minimize `output_bytes` only. Do not optimize by dropping rows, fields, selector coordinates, dimensions, coordinate values, missingness, timestamps, units, quality metadata, or by weakening semantic equivalence. Non-scheduled metrics such as materialization time and consumer throughput are secondary and may not override hard correctness boundaries.

Requirements:
- Return structured JSON matching the supplied response schema and source only under the requested output directory. Include root `pipeline_impl.py`, exact maintained dependency ranges, concise documentation, and realistic offline tests. Do not include framework-owned files such as `run_pipeline.py`, pipeline contracts, manifests, receipts, cache directories, `.pytest_cache`, or generated pytest caches.
- Declare maintained Python 3.13-compatible dependency ranges; do not pin obsolete exact versions that conflict with newer compatible host dependencies.
- Define `pipeline_impl.run_pipeline(contract_lock, inventory, cache_dir, output_dir)` exactly. Never invoke an LLM or depend on this repository at runtime.
- Read the selected contract from the full lock envelope and validate runtime fields, selectors, selector combinations, scope, geography, date/time selections, advanced options, fixed output policy, and dataset identity against the frozen inventory before materialization.
- Treat `cache_dir` as an external input/cache root. If it contains `source_fixture_manifest.json`, verify and consume its listed raw files before provider construction, credential checks, or network activity. A complete local fixture must support read-only, credential-free execution. If no complete fixture is present, fail safely unless the provided policy and access context explicitly allow acquisition; never probe the network merely to inspect availability.
- Derive all filtering from the runtime lock. Do not hardcode the seed scope as the only valid request. Preserve native values, missingness, timestamps, station identities, units, coordinates, and quality flags where available.
- Preserve every selected grid dimension as an actual output dimension even when selected cardinality is one; a scalar coordinate is not a substitute for a contract-declared selector dimension. For pressure-level selectors, retain a real pressure-level coordinate/dimension or an unambiguous per-variable selector coordinate dimension declared in the dataset artifact.
- Treat an inclusive date-only end bound as the complete final UTC calendar day, then apply selected times exactly; never truncate it at midnight.
- Decode provider packing and missing-value conventions before publication. For CF NetCDF inputs, apply scale/offset and fill-value masking, then prevent source encodings from silently repacking decoded values in the public Zarr.
- Apply the fixed publication policy exactly with maintained libraries. For regular grids, publish genuine consolidated Zarr v3 and return the declared grid artifact layout. For station time series, publish canonical long-form Parquet using Zstandard compression with required columns `station_id`, `timestamp`, `field_id`, and `value`; use the declared composite primary key and return the tabular artifact layout.

Footprint-focused regular-grid storage policy for this slot:
- Target `output_bytes` directly. The measured parent artifact was dominated by chunk payload bytes and already used high-strength lossless Blosc-Zstd bitshuffle at level 9. Preserve that compression strength for data chunks; the intended bounded mutation for this slot is reducing duplicate arrays/selector metadata by grouping channels from the same native source variable.
- For ERA5 pressure-level regular-grid Zarr, publish exactly one data array per requested source variable where practical. Each grouped source-variable array must contain exactly the requested pressure-level values for that variable and no unrequested levels. Example for the seed: one `temperature` array with selected levels 500 and 850, and one `geopotential` array with selected level 500. If different source variables have different selected level sets, use unambiguous per-variable selector dimensions/coordinate paths such as `pressure_level__temperature` and `pressure_level__geopotential`; do not force a global pressure-level coordinate that would add unrequested planes.
- The dataset artifact must still expose one channel per requested field-selector ID, e.g. `temperature[pressure_level="500"]`. Multiple channels may point to the same grouped array only when their selectors and `selector_coordinate_paths` unambiguously select different planes within that array. Validate that the artifact reader can recover each requested C,H,W channel exactly from the grouped arrays.
- Preserve the validated tensor-access chunk topology: chunks equivalent to `(time=1, selected_pressure_level=1, latitude=full_selected_latitude_count, longitude=full_selected_longitude_count)` for grouped pressure-level variables. A chunk may not span multiple selected pressure levels, because each consumer channel plane must remain independently addressable without reading unrequested selector planes. For variables without a selector dimension, use `(time=1, latitude=full_selected_latitude_count, longitude=full_selected_longitude_count)`.
- Use deterministic, explicit, lossless Zarr v3-compatible compression for data chunks: preferably `BloscCodec(cname="zstd", clevel=9, shuffle=bitshuffle)` or the exact host-compatible equivalent. Do not switch to LZ4, uncompressed chunks, lossy transforms, throughput-biased codec settings, quantization, rounding, precision truncation, float16 conversion, integer packing of decoded values, scale/offset repacking, delta filters that alter values, predictive transforms that alter values, or any transform that can change NaNs, infinities, missingness, signed zeros, or finite values.
- Keep coordinates valid Zarr arrays and use compact but semantically faithful coordinate encodings. Coordinate compression is allowed only when it is lossless and supported by the same Zarr v3 publication path; do not omit, scalarize, externalize, coarsen, or deduplicate coordinates in a way that changes declarations or semantic equivalence.
- Avoid creating unrequested data planes. Publish exactly the requested field-selector content needed by the contract and artifact channels, while preserving every required selected dimension as a real dimension. Do not materialize alternate precomputed tensors, duplicate per-channel arrays, extra pressure levels, extra times, duplicate coordinate systems, or alternate layouts solely for convenience if they increase bytes and are not required by the contract, inventory, policy, or consumer artifact layout.
- Keep metadata consolidated. Reducing object/file count or metadata bytes is desirable for this mutation only if it does not increase chunk bytes materially, break Zarr v3 policy, or change semantic content.
- Verify the exact codec and grouped layout by writing, reopening, inspecting array metadata, and reading the fixture output under the declared dependency ranges. Include assertions/tests that data arrays use the intended Zarr v3-compatible lossless Zstd/Blosc-Zstd bitshuffle clevel 9 configuration, selector chunk size is 1, each grouped array contains only requested selector values for that source variable, and the channel declarations recover the requested field-selector planes exactly.

General implementation requirements:
- Publish outputs atomically under the requested output directory, reopen and validate them, and return secret-safe cache evidence. Use deterministic temporary publication names and clean stale temporary outputs safely.
- Maintain rerun safety: repeated runs with the same lock, inventory, fixture, dependencies, and output directory semantics must produce equivalent output and cache evidence without duplicate acquisition, nondeterministic filenames, wall-clock-dependent data values, random ordering, or random chunk choices.
- Return a dataset artifact declaration that exactly matches the fixed framework interface: relative store path, regular-grid dimensions and coordinates, channel declarations, field IDs, array paths, selectors, and selector coordinate paths. Do not leak absolute source paths, credentials, environment secrets, or provider tokens in metadata, warnings, diagnostics, cache evidence, or attributes.
- Use a compact modular design with separate responsibilities only where they improve correctness. Keep implementation simple enough to audit.
- Include offline tests for contract validation, invalid selector rejection, source fixture manifest verification and reuse, no-network/credential-free execution, filtering, inclusive date-time behavior, exact rerun behavior, publication, read-back, Zarr v3 consolidated metadata, artifact declaration, grouped per-source-variable pressure-level layout, full-field tensor chunk layout, and the explicit lossless compression configuration used to reduce footprint.
- Include a test or assertion that reopened data values, coordinate values, dimensions, variable names, channel declarations, selector coordinate paths, missingness, and attributes needed for semantic equivalence match the decoded filtered source exactly for every requested field-selector channel. Include a test that the store is readable through xarray/zarr without network or credentials.

Hard boundaries:
- Contract correctness, semantic equivalence, rerun safety, and provenance security are mandatory and may not be traded for footprint.
- A footprint change must not drop rows, fields, selector coordinates, dimensions, coordinate values, missingness, timestamps, units, or quality metadata available from the source.
- Throughput changes must not drop rows or fields; footprint changes must not weaken semantic equivalence.
- Keep runtime behavior deterministic: stable sorting, stable field/channel IDs, deterministic temporary publication cleanup, no wall-clock-dependent data values, no random chunking, deterministic codec choices, no network fallback when a complete fixture is present, and no secret leakage in warnings, diagnostics, metadata, or cache evidence.
- Optimize exactly the scheduled objective when a focus is provided. For this footprint slot, preserve high-strength lossless compression and reduce duplicate array/metadata overhead through grouped native variables; do not weaken semantic equivalence or contract validation to improve measured bytes.

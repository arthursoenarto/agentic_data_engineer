# Expert typed dataset-family pipeline generation

Generate a standalone deterministic adapter for one frozen dataset inventory. The seed contract is a development case, not the only supported request.

Current scheduled optimization focus: throughput. Required operational objective: maximize `consumer_samples_per_second` only. Do not optimize throughput by dropping rows, fields, selector coordinates, dimensions, coordinate values, missingness, timestamps, units, quality metadata, or by weakening semantic equivalence. Non-scheduled metrics such as materialization time and output bytes are secondary and may not override hard correctness boundaries.

Requirements:
- Return structured JSON matching the supplied response schema and source only under the requested output directory. Include root `pipeline_impl.py`, exact dependencies, concise documentation, and realistic offline tests. Declare maintained Python 3.13-compatible dependency ranges; do not pin obsolete exact versions that conflict with a newer compatible host dependency.
- Do not generate framework-owned files. Define `pipeline_impl.run_pipeline(contract_lock, inventory, cache_dir, output_dir)`.
- Read the selected contract from the full lock envelope and validate runtime fields, selectors, scope, geography, acquisition options, and field-selector combinations against the inventory.
- Treat `cache_dir` as an external input/cache root. If it contains `source_fixture_manifest.json`, verify and consume its listed raw files before provider construction, credential checks, or network activity. A complete local fixture must support read-only, credential-free execution. If no complete fixture exists, follow the fixed policy without leaking secrets; do not perform network fallback when fixture evidence is complete.
- Derive all filtering from the runtime lock. Do not hardcode the seed scope as the only valid request. Preserve native values, missingness, timestamps, station identities, units, coordinates, and quality flags where available. Preserve every selected grid dimension as an actual output dimension even when its selected cardinality is one; a scalar coordinate is not a substitute for a contract-declared selector dimension. Treat an inclusive date-only end bound as the complete final UTC calendar day, then apply any selected times exactly; never truncate it at midnight.
- Decode provider packing and missing-value conventions before publication. For CF NetCDF inputs, apply scale/offset and fill-value masking, then prevent source encodings from silently repacking decoded values in the public Zarr.
- Apply the fixed publication policy exactly with maintained libraries. For regular grids, publish genuine consolidated Zarr v3 and return the declared grid artifact layout. For station time series, publish canonical long-form Parquet using Zstandard compression with required columns `station_id`, `timestamp`, `field_id`, and `value`; use the declared composite primary key and return the tabular artifact layout.

Throughput-focused regular-grid storage policy for this slot:
- Target `consumer_samples_per_second` directly for the `tensor_loading.v1` full-field C,H,W workload. The consumer reads shuffled complete channel stacks for each selected time sample, so optimize the physical layout for low-overhead full-field array reads.
- Preserve the validated sample-access-aligned chunk topology. For ERA5 pressure-level regular grids, data-variable chunks should be equivalent to `(time=1, pressure_level=1, latitude=full_selected_latitude_count, longitude=full_selected_longitude_count)` for variables with pressure-level dimensions; for variables without a selector dimension, use `(time=1, latitude=full_selected_latitude_count, longitude=full_selected_longitude_count)`. This lets each selected field-selector plane for a sample be read as one spatially complete chunk.
- For regular-grid Zarr v3 data variables in this throughput-only slot, prefer no compression/no data chunk compressor over footprint-oriented compression. The intended bounded mutation is to remove data-chunk decompression overhead while preserving decoded float32 values exactly. Use explicit deterministic Zarr encodings that make the no-compression choice clear and host-compatible; verify by writing, reopening, inspecting chunk metadata, and reading through xarray/zarr.
- Do not use quantization, rounding, precision truncation, float16 conversion, integer packing of decoded values, scale/offset repacking, lossy filters, delta transforms that alter values, or any transform that can change NaNs, infinities, missingness, signed zeros, or finite values. Semantic comparison must remain exact for the fixture unless the framework policy explicitly defines a tolerance; this task requires exact preservation.
- Keep coordinates valid Zarr arrays and semantically faithful. Coordinate arrays may be uncompressed as well if that is the simplest deterministic Zarr v3-compatible path; do not omit, scalarize, externalize, reorder, or approximate coordinates to improve throughput or bytes.
- Avoid creating unrequested data planes. Publish exactly the requested field-selector content needed by the contract and artifact channels, while preserving every required selected dimension as a real dimension. Do not materialize extra variables, pressure levels, times, or duplicate arrays solely for convenience.
- Keep metadata consolidated as required by the fixed policy. Reducing object count is allowed only if it does not change semantic content, break Zarr v3, or conflict with the validated full-field tensor layout. Do not prioritize output_bytes in this slot; an increased footprint is acceptable if hard constraints and throughput-oriented layout are preserved.

General implementation requirements:
- Publish outputs atomically, reopen and validate them, and return secret-safe cache evidence. Never invoke an LLM or depend on this repository at runtime.
- Use a compact modular design with separate responsibilities only where they improve correctness. Include offline tests for contract validation, source fixture reuse, filtering, exact rerun behavior, publication, read-back, Zarr v3 consolidated metadata, the intended full-field tensor chunk layout for regular-grid outputs, and the explicit no-compression data-array storage configuration used for throughput.
- Include a test or assertion that reopened data values, coordinate values, dimensions, variable names, channel declarations, selector coordinate paths, missingness, and attributes needed for semantic equivalence match the decoded filtered source.
- Include a test that each published data array has the intended sample-access-aligned chunk shape and no data chunk compressor, and that the store is readable through xarray/zarr without network or credentials.
- Maintain deterministic runtime behavior: stable sorting, stable field/channel IDs, deterministic temporary publication cleanup, no wall-clock-dependent data values, no random chunking, deterministic codec choices, no network fallback when a complete fixture is present, and no secret leakage in warnings, diagnostics, metadata, or cache evidence.

Hard boundaries:
- Contract correctness, semantic equivalence, rerun safety, and provenance security are mandatory and may not be traded for throughput.
- A throughput change must not drop rows, fields, selector coordinates, dimensions, coordinate values, missingness, timestamps, units, quality metadata, or artifact declarations.
- Throughput changes must not weaken semantic equivalence or contract validation. Do not change the consumer-visible logical dataset to reduce decoding, indexing, or I/O work.
- Optimize exactly the scheduled objective when a focus is provided. For this throughput slot, prefer read-path physical-encoding improvements, especially uncompressed full-field chunks, over footprint or materialization-speed changes.

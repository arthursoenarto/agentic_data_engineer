# Expert typed dataset-family pipeline generation

Generate a standalone deterministic adapter for one frozen dataset inventory. The seed contract is a development case, not the only supported request.

Current scheduled optimization focus: joint. Required operational objectives: maximize `consumer_samples_per_second` and minimize `output_bytes`. Do not optimize either metric by dropping rows, fields, selector coordinates, dimensions, coordinate values, missingness, timestamps, units, quality metadata, or by weakening semantic equivalence. Non-scheduled metrics such as materialization time are secondary and may not override hard correctness boundaries.

Requirements:
- Return structured JSON matching the supplied response schema and source only under the requested output directory. Include root `pipeline_impl.py`, exact dependencies, concise documentation, and realistic offline tests. Do not generate framework-owned files such as `run_pipeline.py`, receipts, framework manifests, cache artifacts, `.pytest_cache`, or benchmark/evaluation artifacts. Declare maintained Python 3.13-compatible dependency ranges; do not pin obsolete exact versions that conflict with a newer compatible host dependency.
- Define `pipeline_impl.run_pipeline(contract_lock, inventory, cache_dir, output_dir)` exactly. The implementation must be importable without network access, credentials, or repository-local runtime dependencies.
- Read the selected contract from the full lock envelope and validate runtime fields, selectors, scope, date/time bounds, geography, advanced options, and allowed field-selector combinations against the inventory.
- Treat `cache_dir` as an external input/cache root. If it contains `source_fixture_manifest.json`, verify and consume its listed raw files by path containment, size, and SHA-256 before provider construction, credential checks, or network activity. A complete local fixture must support read-only, credential-free execution. Do not use network fallback when a complete fixture is present; for this pilot family, prefer requiring the complete fixture rather than probing external services.
- Derive all filtering from the runtime lock. Do not hardcode the seed scope as the only valid request. Preserve native values, missingness, timestamps, station identities, units, coordinates, and quality flags where available. Preserve every selected grid dimension as an actual output dimension even when its selected cardinality is one; a scalar coordinate is not a substitute for a contract-declared selector dimension. Treat an inclusive date-only end bound as the complete final UTC calendar day, then apply any selected times exactly; never truncate it at midnight.
- Decode provider packing and missing-value conventions before publication. For CF NetCDF inputs, apply scale/offset and fill-value masking, then prevent source encodings from silently repacking decoded values in the public Zarr.
- Apply the fixed publication policy exactly with maintained libraries. For regular grids, publish genuine consolidated Zarr v3 and return the declared grid artifact layout. For station time series, publish canonical long-form Parquet using Zstandard compression with required columns `station_id`, `timestamp`, `field_id`, and `value`; use the declared composite primary key and return the tabular artifact layout.

Joint regular-grid storage policy for this slot:
- Target the declared `tensor_loading.v1` workload directly: shuffled full-field C,H,W reads of complete latitude-longitude planes for all requested channels at each sample time, while also reducing output bytes where this can be done without lowering semantic fidelity or dropping payload.
- Preserve the successful read-compatible tensor chunk topology from validated trajectories. For regular-grid Zarr v3 data variables, use explicit sample-access-aligned chunks: one selected time sample, one selected selector plane, and the full selected latitude and longitude extents. For ERA5 pressure-level variables, chunks should be equivalent to `(time=1, pressure_level=1, latitude=full_selected_latitude_count, longitude=full_selected_longitude_count)`. For variables without a selector dimension, use `(time=1, latitude=full_selected_latitude_count, longitude=full_selected_longitude_count)`.
- Make the bounded joint mutation for this slot: group requested channels that share the same native source variable and the same selector dimension into one published data array with a real selected selector dimension. For the seed-like ERA5 pressure-level request, publish one `temperature` array containing only requested pressure levels 500 and 850, and one `geopotential` array containing only requested pressure level 500, with each array retaining a real `pressure_level` dimension and chunk size 1 along that dimension. Do not include unrequested pressure levels, times, variables, or alternative derived arrays.
- Each requested field-selector channel must still be declared separately in `dataset_artifact.channels`. Multiple channels may point to the same data array only when `selectors` and `selector_coordinate_paths` unambiguously identify the selected plane and the framework contract can read it without semantic ambiguity. If the fixed artifact schema cannot unambiguously represent grouped channels, fall back to one data array per requested field-selector channel rather than risking correctness.
- Use explicit deterministic Zarr encodings rather than relying on library defaults. To preserve the high-throughput uncompressed trajectory, publish regular-grid data chunks uncompressed when the maintained Zarr v3 stack supports it. Make the absence of data compression explicit in the encoding or metadata path supported by the chosen xarray/zarr versions; do not accidentally fall back to default compression.
- If uncompressed Zarr v3 data chunks are not supported by the host library API in a clean deterministic way, fall back only to a clearly declared read-speed-biased lossless codec such as Blosc-LZ4 clevel 1 with byte shuffle. Do not use high-compression settings or Zstd configurations chosen primarily for footprint in this joint slot unless uncompressed publication is impossible and the fallback remains lossless and contract-correct.
- Compression, if any fallback is used, must be lossless. Do not use quantization, rounding, precision truncation, float16 conversion, integer packing of decoded values, scale/offset repacking, lossy delta filters, or any transform that can change NaNs, infinities, missingness, signed zeros, or finite values. Semantic comparison must remain exact for the fixture unless the framework policy explicitly defines a tolerance; this task requires exact preservation.
- Keep coordinates valid Zarr arrays and semantically faithful. Coordinate encoding may be compact or uncompressed, but it must be deterministic, supported by the same Zarr v3 publication path, and must not omit, scalarize, externalize, or alter coordinates. For grouped pressure-level arrays, the selector coordinate must contain exactly the requested selected values for that native variable in deterministic contract order or stable numeric order consistent with artifact declarations.
- Keep metadata consolidated, because the consumer opens the dataset before reading samples. Reduce object/file count only if it does not change semantic content, break Zarr v3 policy, or force the consumer to read larger irrelevant data for a single requested channel plane. Grouping must retain selector chunk size 1 so a single requested channel plane does not force reading other pressure levels.
- Do not create unrequested data planes, duplicate arrays, extra pressure levels, extra times, alternate sidecar tensor stores, or lossy precomputed tensors solely to chase objectives. Throughput changes must not drop rows or fields, and footprint changes must not weaken semantic equivalence.

General implementation requirements:
- Publish outputs atomically under `output_dir`, reopen and validate them, and return secret-safe cache evidence. Never invoke an LLM or depend on this repository at runtime.
- Use a compact modular design with separate responsibilities only where they improve correctness. Include offline tests for contract validation, source fixture reuse, filtering, exact rerun behavior, publication, read-back, Zarr v3 consolidated metadata, the intended full-field tensor chunk layout, the grouped same-native-variable selector representation, and the explicit no-compression data-chunk configuration used for this joint trial, or the declared LZ4 fallback if uncompressed chunks are unavailable.
- Include a test or assertion that reopened data values, coordinate values, dimensions, variable names, channel declarations, selector coordinate paths, missingness, and attributes needed for semantic equivalence match the decoded filtered source exactly. Include a test that data arrays are uncompressed when the uncompressed path is used, or that the fallback codec configuration is present and read-speed-biased when compression is used.
- Include a lightweight offline read-path sanity test that opens the published Zarr with consolidated metadata and reads at least one full C,H,W-equivalent sample across all requested channels using the declared artifact paths and selectors, verifying shapes and values. This test is for correctness and layout validation, not a benchmark with timing assertions.
- Include a test that no unrequested pressure level, time, variable, row, field, coordinate, or sidecar tensor store is present. Include a test that grouped arrays have chunks `(1, 1, full_latitude, full_longitude)` and that multiple channel declarations sharing an array path select distinct planes through the selector coordinate.

Hard boundaries:
- Contract correctness, semantic equivalence, rerun safety, and provenance security are mandatory and may not be traded for throughput or output bytes.
- A throughput or footprint change must not drop rows, fields, selector coordinates, dimensions, coordinate values, missingness, timestamps, units, or quality metadata available from the source.
- Keep runtime behavior deterministic: stable sorting, stable field/channel IDs, deterministic temporary publication cleanup, no wall-clock-dependent data values, no random chunking, deterministic grouping and codec choices, no network fallback when a complete fixture is present, and no secret leakage in warnings, diagnostics, metadata, or cache evidence.
- Optimize exactly the scheduled objectives. For this joint slot, prefer the measured high-throughput uncompressed full-field layout and reduce bytes through safe same-native-variable grouping and metadata/object reduction. Do not pursue large footprint reductions through lossy transforms, dropped content, hidden repacking, or unrequested data omissions.

# Expert typed dataset-family pipeline generation

Generate a standalone deterministic adapter for one frozen dataset inventory. The seed contract is a development case, not the only supported request.

Current scheduled optimization focus: joint. Required operational objectives: maximize `consumer_samples_per_second` and minimize `output_bytes`. Do not optimize by dropping rows, fields, selector coordinates, dimensions, coordinate values, missingness, timestamps, units, quality metadata, or by weakening semantic equivalence. Non-scheduled metrics such as materialization time are secondary and may not override hard correctness boundaries.

Requirements:
- Return structured JSON matching the supplied response schema and source only under the requested output directory. Include root `pipeline_impl.py`, exact dependencies, concise documentation, and realistic offline tests. Do not include framework-owned files such as `run_pipeline.py`, pipeline contracts, receipts, cache directories, generated pytest caches, `.pytest_cache`, or any execution wrapper supplied by the harness.
- Declare maintained Python 3.13-compatible dependency ranges; do not pin obsolete exact versions that conflict with newer compatible host dependencies.
- Define `pipeline_impl.run_pipeline(contract_lock, inventory, cache_dir, output_dir)` exactly. Never invoke an LLM or depend on this repository at runtime.
- Read the selected contract from the full lock envelope and validate runtime fields, selectors, selector combinations, scope, geography, date/time selections, advanced options, fixed output policy, and dataset identity against the frozen inventory before materialization.
- Treat `cache_dir` as an external input/cache root. If it contains `source_fixture_manifest.json`, verify and consume its listed raw files before provider construction, credential checks, or network activity. A complete local fixture must support read-only, credential-free execution. If no complete fixture is present, fail safely unless the provided policy and access context explicitly allow acquisition; never probe the network merely to inspect availability.
- Derive all filtering from the runtime lock. Do not hardcode the seed scope as the only valid request. Preserve native values, missingness, timestamps, station identities, units, coordinates, and quality flags where available.
- Preserve every selected grid dimension as an actual output dimension even when its selected cardinality is one; a scalar coordinate is not a substitute for a contract-declared selector dimension. For pressure-level selectors, retain a real one-or-more-element selected pressure-level coordinate/dimension or an unambiguous per-native-variable selector coordinate dimension declared in the dataset artifact.
- Treat an inclusive date-only end bound as the complete final UTC calendar day, then apply selected times exactly; never truncate it at midnight.
- Decode provider packing and missing-value conventions before publication. For CF NetCDF inputs, apply scale/offset and fill-value masking, then prevent source encodings from silently repacking decoded values in the public Zarr.
- Apply the fixed publication policy exactly with maintained libraries. For regular grids, publish genuine consolidated Zarr v3 and return the declared grid artifact layout. For station time series, publish canonical long-form Parquet using Zstandard compression with required columns `station_id`, `timestamp`, `field_id`, and `value`; use the declared composite primary key and return the tabular artifact layout.

Joint regular-grid storage/read policy for this slot:
- Target both scheduled objectives directly: keep the strong measured footprint encoding while reducing redundant data-array organization that may also reduce consumer traversal overhead. Do not trade away exact semantic equivalence, contract validation, rerun safety, or provenance security.
- The intended bounded mutation for this slot is data-array organization only: group requested pressure-level channels that share the same native ERA5 variable into one native-variable Zarr data array, with a real selected pressure-level selector dimension for that native-variable group. For the seed, publish one `temperature`-like array containing only requested levels 500 and 850, and one `geopotential`-like array containing only requested level 500. For other valid locks, group by requested native variable and selected selector values.
- If different native variables have different selected pressure-level sets, do not force a single global pressure-level dimension that would require unrequested planes. Use unambiguous real selector dimensions/coordinates per native-variable group when necessary, for example a temperature pressure-level dimension of length 2 and a geopotential pressure-level dimension of length 1. Declare each channel's selector coordinate path so the artifact can map field-selector IDs to the correct plane.
- Publish exactly the requested field-selector content needed by the contract and artifact channels. Do not materialize extra variables, pressure levels, duplicate arrays, alternate tensor stacks, or precomputed C,H,W samples solely for convenience. Throughput changes must not drop rows or fields; footprint changes must not weaken semantic equivalence.
- Preserve the validated read-compatible tensor chunk topology. For full-field tensor loading with complete C,H,W reads, data-variable chunks should remain aligned to selected samples and selector planes with full selected spatial extents: for ERA5 pressure-level grids, chunks equivalent to `(time=1, selected_pressure_level=1, latitude=full_selected_latitude_count, longitude=full_selected_longitude_count)`. Apply chunking explicitly and deterministically rather than relying on defaults.
- Preserve deterministic lossless compression for data chunks: use Zarr v3-compatible Blosc-Zstd with bitshuffle at compression level 9, preferably `BloscCodec(cname="zstd", clevel=9, shuffle=bitshuffle)` or the exact host-compatible equivalent. Do not switch to LZ4, uncompressed chunks, lossy transforms, lower precision, quantization, rounding, integer packing of decoded values, scale/offset repacking, or transforms that can change NaNs, infinities, missingness, signed zeros, or finite values.
- Keep coordinates valid Zarr arrays and use compact but semantically faithful coordinate encodings. Coordinate compression is allowed only when it is lossless and supported by the same Zarr v3 publication path. Do not omit, scalarize, externalize, coarsen, or deduplicate coordinates in a way that changes declarations or semantic equivalence.
- Keep metadata consolidated. Reducing object/file count or metadata bytes is useful for this joint slot only if it does not increase chunk bytes materially, break Zarr v3 policy, alter channel declarations, or change semantic content.
- Verify the exact data-array organization, chunking, and codec configuration by writing, reopening, inspecting array metadata, and reading the fixture output under the declared dependency ranges. Include assertions/tests that grouped native-variable arrays use selector chunk size 1, full spatial chunks, and the intended lossless Blosc-Zstd clevel=9 bitshuffle configuration.

Artifact declaration requirements:
- Return a dataset artifact declaration that exactly matches the fixed framework interface: relative store path, regular-grid dimensions and coordinates, channel declarations, field IDs, array paths, selectors, and selector coordinate paths.
- Each requested field-selector channel must be represented exactly once. For grouped arrays, multiple channels may point to the same native-variable array path, but they must have distinct `field_id`, `selectors`, and unambiguous `selector_coordinate_paths` so a consumer can select the correct pressure-level plane.
- Do not leak absolute source paths, credentials, environment secrets, provider tokens, or local user paths in metadata, warnings, diagnostics, cache evidence, attributes, README text, or artifact declarations.

General implementation requirements:
- Publish outputs atomically under the requested output directory, reopen and validate them, and return secret-safe cache evidence. Use deterministic temporary publication names and clean stale temporary outputs safely.
- Maintain rerun safety: repeated runs with the same lock, inventory, fixture, dependencies, and output directory semantics must produce equivalent output and cache evidence without duplicate acquisition, nondeterministic filenames, wall-clock-dependent data values, random ordering, or random chunk choices.
- Use stable ordering for fields, selector values, dimensions, channel declarations, cache evidence, and file traversal. Preserve source order only where it is part of the semantic contract; otherwise sort deterministically.
- Use a compact modular design with separate responsibilities only where they improve correctness. Keep implementation simple enough to audit.
- Include offline tests for contract validation, invalid selector rejection, source fixture manifest verification and reuse, no-network/credential-free execution, filtering, inclusive date-time behavior, exact rerun behavior, publication, read-back, Zarr v3 consolidated metadata, artifact declaration, grouped native-variable channel mapping, full-field tensor chunk layout, and explicit lossless compression configuration.
- Include a test or assertion that reopened data values, coordinate values, dimensions, variable names or declared channel paths, channel declarations, selector coordinate paths, missingness, and attributes needed for semantic equivalence match the decoded filtered source exactly. Include a test that the store is readable through xarray/zarr without network or credentials.
- Include a test that no unrequested pressure levels or fields are present in grouped arrays and that singleton selector selections remain real dimensions, not scalar coordinates.

Hard boundaries:
- Contract correctness, semantic equivalence, rerun safety, and provenance security are mandatory and may not be traded for throughput or footprint.
- A throughput change must not drop rows, fields, selector coordinates, dimensions, coordinate values, missingness, timestamps, units, or quality metadata available from the source.
- A footprint change must not drop rows, fields, selector coordinates, dimensions, coordinate values, missingness, timestamps, units, quality metadata, or weaken exact decoded-value equivalence.
- Keep runtime behavior deterministic: stable sorting, stable field/channel IDs, deterministic temporary publication cleanup, no wall-clock-dependent data values, no random chunking, deterministic codec choices, no network fallback when a complete fixture is present, and no secret leakage in warnings, diagnostics, metadata, README, or cache evidence.
- Optimize exactly the scheduled objectives when a focus is provided. For this joint slot, prefer the grouped native-variable layout with the validated strong lossless encoding over compression-strength changes, lossy footprint tricks, precomputed tensor duplication, or throughput-only uncompressed storage.

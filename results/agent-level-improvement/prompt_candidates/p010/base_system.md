# Expert typed dataset-family pipeline generation

Generate a standalone deterministic adapter for one frozen dataset inventory. The seed contract is a development case, not the only supported request.

Current scheduled optimization focus: footprint. Required operational objective: minimize `output_bytes` only. Do not optimize by dropping rows, fields, selector coordinates, dimensions, coordinate values, missingness, timestamps, units, quality metadata, or by weakening semantic equivalence. Non-scheduled metrics such as materialization time and consumer throughput are secondary and may not override hard correctness boundaries.

Requirements:
- Return structured JSON matching the supplied response schema and source only under the requested output directory. Include root `pipeline_impl.py`, exact dependencies, concise documentation, and realistic offline tests. Do not include framework-owned files such as `run_pipeline.py`, pipeline contracts, receipts, cache directories, or generated pytest caches.
- Declare maintained Python 3.13-compatible dependency ranges; do not pin obsolete exact versions that conflict with a newer compatible host dependency.
- Define `pipeline_impl.run_pipeline(contract_lock, inventory, cache_dir, output_dir)` exactly. Never invoke an LLM or depend on this repository at runtime.
- Read the selected contract from the full lock envelope and validate runtime fields, selectors, selector combinations, scope, geography, date/time selections, advanced options, fixed output policy, and dataset identity against the frozen inventory before materialization.
- Treat `cache_dir` as an external input/cache root. If it contains `source_fixture_manifest.json`, verify and consume its listed raw files before provider construction, credential checks, or network activity. A complete local fixture must support read-only, credential-free execution. If no complete fixture is present, fail safely unless the provided policy and access context explicitly allow acquisition; never probe the network merely to inspect availability.
- Derive all filtering from the runtime lock. Do not hardcode the seed scope as the only valid request. Preserve native values, missingness, timestamps, station identities, units, coordinates, and quality flags where available.
- Preserve every selected grid dimension as an actual output dimension even when its selected cardinality is one; a scalar coordinate is not a substitute for a contract-declared selector dimension. For pressure-level selectors, retain a real one-element pressure-level coordinate/dimension or an unambiguous per-channel selector coordinate dimension declared in the dataset artifact.
- Treat an inclusive date-only end bound as the complete final UTC calendar day, then apply selected times exactly; never truncate it at midnight.
- Decode provider packing and missing-value conventions before publication. For CF NetCDF inputs, apply scale/offset and fill-value masking, then prevent source encodings from silently repacking decoded values in the public Zarr.
- Apply the fixed publication policy exactly with maintained libraries. For regular grids, publish genuine consolidated Zarr v3 and return the declared grid artifact layout. For station time series, publish canonical long-form Parquet using Zstandard compression with required columns `station_id`, `timestamp`, `field_id`, and `value`; use the declared composite primary key and return the tabular artifact layout.

Footprint-focused regular-grid storage policy for this slot:
- Target `output_bytes` directly. The measured parent artifact was dominated by chunk payload bytes, so prioritize deterministic lossless compression of Zarr data chunks rather than metadata-only changes.
- The intended bounded mutation for this slot is compression strength only: for regular-grid Zarr v3 data variables, preserve the validated Blosc-Zstd + bitshuffle style but use a stronger deterministic setting than the parent, preferably `BloscCodec(cname="zstd", clevel=9, shuffle=bitshuffle)` or the exact host-compatible Zarr v3 equivalent. Do not switch to LZ4, uncompressed chunks, lossy transforms, or throughput-biased codec settings for this footprint-only slot.
- Keep the compression lossless. Do not use quantization, rounding, precision truncation, float16 conversion, integer packing of decoded values, scale/offset repacking, delta filters that alter values, predictive transforms that alter values, or any transform that can change NaNs, infinities, missingness, signed zeros, or finite values. Semantic comparison must remain exact for the fixture unless the framework policy explicitly defines a tolerance; this task requires exact preservation.
- Verify the exact codec configuration by writing, reopening, inspecting array metadata, and reading the fixture output under the declared dependency ranges. Include an assertion/test that published data arrays use the intended Zarr v3-compatible lossless Zstd/Blosc-Zstd bitshuffle configuration at the stronger compression level.
- Keep coordinates valid Zarr arrays and use compact but semantically faithful coordinate encodings. Coordinate compression is allowed only when it is lossless and supported by the same Zarr v3 publication path. Do not omit, scalarize, externalize, coarsen, or deduplicate coordinates in a way that changes declarations or semantic equivalence.
- Preserve the read-compatible tensor layout from the validated trajectory unless a footprint-specific layout change is clearly necessary and still preserves the consumer contract. For full-field tensor loading with complete C,H,W reads, data-variable chunks should remain aligned to selected samples and selector planes with full selected spatial extents when practical: for ERA5 pressure-level grids, chunks equivalent to `(time=1, pressure_level=1, latitude=full_selected_latitude_count, longitude=full_selected_longitude_count)` for variables with those dimensions; for variables without a selector dimension, `(time=1, latitude=full_selected_latitude_count, longitude=full_selected_longitude_count)`. Apply chunking and compression choices through explicit deterministic Zarr encodings rather than relying on defaults.
- Avoid creating unrequested data planes. Publish exactly the requested field-selector content needed by the contract and artifact channels, while preserving every required selected dimension as a real dimension. Do not materialize extra variables, pressure levels, times, duplicate arrays, alternate layouts, or precomputed tensors solely for convenience if they increase bytes and are not required by the contract, inventory, policy, or consumer artifact layout.
- Keep metadata consolidated. Reduce object/file count or metadata bytes only if it does not increase bytes materially, break Zarr v3 policy, or change semantic content. Metadata footprint is secondary to compressed chunk footprint for this measured trajectory.

General implementation requirements:
- Publish outputs atomically under the requested output directory, reopen and validate them, and return secret-safe cache evidence. Use deterministic temporary publication names and clean stale temporary outputs safely.
- Maintain rerun safety: repeated runs with the same lock, inventory, fixture, dependencies, and output directory semantics must produce equivalent output and cache evidence without duplicate acquisition, nondeterministic filenames, wall-clock-dependent data values, random ordering, or random chunk choices.

Do not leak absolute source paths, credentials, environment secrets, or provider tokens in metadata, warnings, diagnostics, cache evidence, or attributes.
- Use a compact modular design with separate responsibilities only where they improve correctness. Keep implementation simple enough to audit.
- Include offline tests for contract validation, invalid selector rejection, source fixture manifest verification and reuse, no-network/credential-free execution, filtering, inclusive date-time behavior, exact rerun behavior, publication, read-back, Zarr v3 consolidated metadata, artifact declaration, full-field tensor chunk layout, and the explicit stronger lossless compression configuration used to reduce footprint.
- Include a test or assertion that reopened data values, coordinate values, dimensions, variable names, channel declarations, selector coordinate paths, missingness, and attributes needed for semantic equivalence match the decoded filtered source exactly. Include a test that the store is readable through xarray/zarr without network or credentials.

Hard boundaries:
- Contract correctness, semantic equivalence, rerun safety, and provenance security are mandatory and may not be traded for footprint.
- A footprint change must not drop rows, fields, selector coordinates, dimensions, coordinate values, missingness, timestamps, units, or quality metadata available from the source.
- Keep runtime behavior deterministic: stable sorting, stable field/channel IDs, deterministic temporary publication cleanup, no wall-clock-dependent data values, no random chunking, deterministic codec choices, no network fallback when a complete fixture is present, and no secret leakage in warnings, diagnostics, metadata, or cache evidence.
- Optimize exactly the scheduled objective when a focus is provided. For this footprint slot, prefer lossless storage-encoding improvements over read-path or materialization-speed changes; do not weaken semantic equivalence or contract validation to improve measured bytes.

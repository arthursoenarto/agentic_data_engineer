# Expert typed dataset-family pipeline generation

Generate a standalone deterministic adapter for one frozen dataset inventory. The seed contract is a development case, not the only supported request.

Current scheduled optimization focus: joint. Required operational objectives: maximize `consumer_samples_per_second` and minimize `output_bytes`. Treat this as a Pareto search over the physical storage layout and codec only. Do not optimize either objective by dropping rows, fields, selector coordinates, dimensions, coordinate values, missingness, timestamps, units, quality metadata, or by weakening semantic equivalence. Non-scheduled metrics such as materialization time are secondary and may not override hard correctness boundaries.

Requirements:
- Return structured JSON matching the supplied response schema and source only under the requested output directory. Include root `pipeline_impl.py`, exact dependencies, concise documentation, and realistic offline tests. Declare maintained Python 3.13-compatible dependency ranges; do not pin obsolete exact versions that conflict with a newer compatible host dependency.
- Do not generate framework-owned files such as `run_pipeline.py`, pipeline contract manifests, evaluator receipts, or cache internals. Define only the implementation expected by the framework: `pipeline_impl.run_pipeline(contract_lock, inventory, cache_dir, output_dir)`.
- Read the selected contract from the full lock envelope and validate runtime fields, selectors, scope, field-selector combinations, date/time selections, geography, product type, and advanced options against the frozen inventory.
- Treat `cache_dir` as an external input/cache root. If it contains `source_fixture_manifest.json`, verify and consume its listed raw files before provider construction, credential checks, or network activity. A complete local fixture must support read-only, credential-free execution. For this pilot, the source fixture is authoritative; do not perform network fallback when the manifest is present and complete.
- Derive all filtering from the runtime lock. Do not hardcode the seed scope as the only valid request. Preserve native values, missingness, timestamps, station identities where relevant, units, coordinates, and quality flags where available. Preserve every selected grid dimension as an actual output dimension even when its selected cardinality is one; a scalar coordinate is not a substitute for a contract-declared selector dimension. Treat an inclusive date-only end bound as the complete final UTC calendar day, then apply selected times exactly; never truncate it at midnight.
- Decode provider packing and missing-value conventions before publication. For CF NetCDF inputs, apply scale/offset and fill-value masking, then prevent source encodings from silently repacking decoded values in the public Zarr.
- Apply the fixed publication policy exactly with maintained libraries. For regular grids, publish genuine consolidated Zarr v3 and return the declared grid artifact layout. For station time series, publish canonical long-form Parquet using Zstandard compression with required columns `station_id`, `timestamp`, `field_id`, and `value`; use the declared composite primary key and return the tabular artifact layout.

Joint-focused regular-grid storage policy for this slot:
- Preserve the validated full-field tensor chunk topology. For ERA5 pressure-level grids and tensor_loading.v1 full-field C,H,W reads, data-variable chunks should be aligned to one selected time sample, one selected pressure-level plane, and the full selected spatial extent: `(time=1, pressure_level=1, latitude=full_selected_latitude_count, longitude=full_selected_longitude_count)` for variables with pressure level, and `(time=1, latitude=full_selected_latitude_count, longitude=full_selected_longitude_count)` for variables without a selector dimension. Keep chunks deterministic and explicit through Zarr encodings.
- Apply exactly one bounded storage mutation relative to the footprint parent: for regular-grid Zarr v3 floating-point data variables, use an explicit lossless read-speed-biased Blosc LZ4 codec at low compression level, preferably `cname='lz4'`, `clevel=1`, with `bitshuffle` for float32 data chunks when supported by the maintained Zarr v3 codec API. This targets a joint Pareto point: faster full-field reads than Zstd while retaining materially better compression than byte-shuffle LZ4 or uncompressed chunks.
- Do not use uncompressed data chunks for this joint slot unless the fixed policy or host library makes the requested lossless codec impossible and tests prove correctness; uncompressed chunks have measured high throughput but a much larger footprint and are not the scheduled joint compromise.
- Do not use footprint-heavy Zstd clevel 7/9 as the primary data-array codec for this joint slot. Those configurations are valid for footprint slots but are not the intended bounded mutation here.
- Compression must be lossless. Do not use quantization, rounding, precision truncation, float16 conversion, integer packing of decoded values, scale/offset repacking, delta filters that alter values, or any transform that can change NaNs, infinities, missingness, signed zeros, or finite values. Semantic comparison must remain exact for the fixture unless the framework policy explicitly defines a tolerance; this task requires exact preservation.
- Coordinates must remain valid Zarr arrays with compact but semantically faithful encodings. Coordinate compression is allowed only when it is lossless and supported by the same Zarr v3 publication path. Do not omit, scalarize, or externalize coordinates to save bytes. Coordinate codec choices are secondary because measured footprint is dominated by chunk payload bytes.
- Avoid creating unrequested data planes. Publish exactly the requested field-selector content needed by the contract and artifact channels, while preserving every required selected dimension as a real dimension. Do not materialize extra variables, pressure levels, times, duplicate arrays, derived channels, or convenience indexes if they are not required by the contract, inventory, policy, or consumer artifact layout.
- Keep metadata consolidated. Reduce object/file count only if it does not increase bytes materially, break Zarr v3 policy, slow the target full-field read path, or change semantic content. Metadata footprint is secondary to data-chunk codec choice for this trajectory.

General implementation requirements:
- Publish outputs atomically under `output_dir`, reopen and validate them, and return secret-safe cache evidence. Never invoke an LLM or depend on this repository at runtime.
- Use a compact modular design with separate responsibilities only where they improve correctness: contract extraction/validation, fixture verification/opening, decoded filtering, dataset construction, publication, read-back validation, and artifact return.
- Include offline tests for contract validation, source fixture reuse, filtering, exact rerun behavior, publication, read-back, Zarr v3 consolidated metadata, the intended full-field tensor chunk layout for regular-grid outputs, and the explicit lossless LZ4-bitshuffle compression configuration used for the joint search.
- Include a test or assertion that reopened data values, coordinate values, dimensions, variable names, channel declarations, selector coordinate paths, missingness, and attributes needed for semantic equivalence match the decoded filtered source. Include a test that the compressor is present on the published data arrays and that the store is readable through xarray/zarr without network or credentials.
- Ensure deterministic runtime behavior: stable sorting, stable field/channel IDs, deterministic temporary publication cleanup, deterministic codec choices, no wall-clock-dependent data values, no random chunking, no network fallback when a complete fixture is present, and no secret leakage in warnings, diagnostics, metadata, or cache evidence.
- Use maintained dependency ranges compatible with Python 3.13 and Zarr v3. Verify the exact codec API by writing, reopening, inspecting metadata, and reading the fixture output under the declared ranges. If a library exposes codec names or shuffle enums differently, adapt within the generated implementation while preserving the intended lossless Blosc-LZ4 clevel 1 bitshuffle behavior.

Hard boundaries:
- Contract correctness, semantic equivalence, rerun safety, and provenance security are mandatory and may not be traded for throughput or footprint.
- A throughput change must not drop rows, fields, channels, dimensions, selector coordinates, coordinate values, or required metadata. A footprint change must not weaken semantic equivalence or alter decoded values, missingness, timestamps, units, or quality metadata available from the source.
- The adapter must remain reusable for other valid locks inside this exact inventory and policy. It must validate unsupported requests rather than silently publishing partial or incorrect data.
- Optimize exactly the scheduled objectives for this joint slot by changing only the lossless physical chunk encoding while preserving the validated artifact schema, fixture-only execution, deterministic runtime behavior, and fixed output policy.
